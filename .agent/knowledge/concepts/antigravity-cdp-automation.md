# Antigravity CDP UI Automation Guidelines

## Summary
When building automation for the Chrome DevTools Protocol (CDP) to auto-accept dialogs generated by the IDE or web application, matching string literals is dangerous and prone to failure when UI copy changes. We must use broad keyword matching, especially to guard against destructive actions.

## Key Insights
- Dialog copy varies between updates and contexts (e.g., "Confirm Undo" vs "Revert changes").
- A guard checking for strict equality (e.g., `text === 'undo action'`) will fail to prevent destructive auto-clicks.

## Gotchas & Pitfalls
- **Destructive Auto-Accepts:** Creating a catch-all "Confirm" button clicker might accidentally approve an "Undo" dialog triggered by a keyboard shortcut. 
  - **Solution:** Explicitly check `['undo', 'revert', 'discard'].some(kw => text.toLowerCase().includes(kw))` to block the auto-click handler on destructive dialogs.
