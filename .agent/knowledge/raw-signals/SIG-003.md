# SIG-003: YAML Frontmatter Non-Compliance Across 62 Skills

## Signal
Audit revealed that 62 out of 65 SKILL.md files had non-standard YAML frontmatter — custom fields (`category`, `triggers`, `coordinates_with`, `success_metrics`) were placed at top-level instead of inside the required `metadata:` block.

## Context
The Claude Skill Guide specifies only `name`, `description`, `license`, `compatibility`, `allowed-tools`, and `metadata` as valid top-level YAML fields. All custom fields must be nested under `metadata:`. PikaKit skills had been created before this standard was enforced.

## Resolution
Wrote automated script (`fix-frontmatter.mjs`) to:
1. Find all SKILL.md files recursively
2. Parse YAML frontmatter
3. Move non-standard top-level fields into `metadata:` block
4. Preserve all existing content

Script executed: 62 files fixed, 0 errors, git checkpoint created before execution.

## Lesson
When a spec defines strict field placement rules, enforce compliance with automated tooling rather than manual edits. For bulk changes (10+ files), always: (1) dry-run first, (2) git checkpoint, (3) execute, (4) spot-check.
