# SIG-004: Knowledge Wiki Architecture Matches Karpathy Model but Lacks Content

## Signal
Comprehensive audit of `.agent/knowledge/` against Karpathy's LLM Knowledge Base methodology revealed excellent architectural alignment (~90%) but nearly empty content (1 concept, 1 signal, 1 ADR out of a target of 100+ articles).

## Context
Karpathy's model: raw data → LLM-compiled .md wiki → cross-linked concept articles → Q&A → linting → search tools. PikaKit implements: `raw-signals/` → `knowledge-compiler` → `concepts/` → `_index.md` + `_graph.md` → `knowledge-linter`. Pipeline exists but has barely been used.

## Resolution
Identified 3 immediate fixes:
1. `_graph.md` was stale (said "No concepts yet" despite article existing)
2. `import-patterns.md` had data corruption on line 91
3. `raw/` and `raw-signals/` directories create ambiguity (Karpathy uses single `raw/`)

## Lesson
Architecture without data is a museum without art. The knowledge pipeline must be actively fed with real signals from every significant coding session to build compound value over time. Design is 10% of the problem; consistent usage is 90%.
